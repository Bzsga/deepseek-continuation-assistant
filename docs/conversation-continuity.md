# 接着上次聊

1.0.4 起，续聊内容可以同时携带已有档案、关键互动片段和最近几轮对话。原话用于保留对话顺序与上下文，帮助新会话接住未完的话题；这不保证新会话具有相同表现，也不表示同一个会话实例被搬到了新窗口。

## 使用

1.0.5 的默认流程是“导入 → 智能整理 → 直接续聊”。新建档案默认开启接续功能，无需先挑选原话、回忆重点或填写交流方式。旧档案和已经保存的关闭状态保持原样，可以在“调整（可选）”中修改。

- “最近对话”携带最近几轮已选原话，可以关闭。
- 智能整理在同一次请求中识别有依据的交流偏好、后来纠正、共同说法和未完话题；没有相应内容就不补写。自动线索保留原消息来源，同一聊天版本按来源顺序呈现变化，不把助手的猜测当成用户偏好。
- 关键原话根据自动线索、重要原话和固定条目的来源推荐。想调整时再展开手动选择，也可以恢复自动选择。
- “希望延续的交流方式”是可选补充，例如现在希望少一点总结。已有填写内容继续保留，不要求回顾整个聊天。
- “接下来想说的话”放在导出内容最后；填写后，新会话可直接回应这句话。

保存设置后，复制和文件导出都会使用最新内容。自动提取融入已有整理请求，不额外发送一轮请求；普通整理仍按原规则计次或计费。仅调整续聊设置在本机完成，不消耗整理次数。旧摘要不会在升级时自动重新请求模型；原文模式继续在本机打包，不宣称已经做了语义识别。

## 重新整理已有档案

1.0.6 起，结果页和档案详情提供“重新整理”。确认原文范围、整理服务及预计次数或费用后，会生成一份新版；原档案保持可用，不需要重新导入 ZIP。

新版继承开始整理时的手动修改、删除、固定条目、补充背景和续聊设置，普通旧摘要不直接混入新结果。与手动内容来源重叠的新建议保存在“核对冲突”，默认沿用你的内容；需要时再选择保留当前或采用整组建议。删除标记仍然有效，不会因为新摘要的编号改变就恢复已删除的信息。

重新整理会使用当前服务重新请求模型，按正常规则计次或计费，不把旧摘要缓存当作本次新结果。已有未完成的整理会先返回其进度，暂停后继续会复用本轮已完成内容；不会因重复点击再启动一份相同的在途整理。原档案可以查看新版，新版及其进度页可以返回原档案。

较旧档案缺少选择范围时，会尝试从保留的整理任务恢复一致且能核实的上次范围，并在发送前说明。原文缺失或历史范围不能确定时，会提示重新选择，不自行扩大到整段聊天或其他版本。删除原档案不会使已经生成的新版失效。

## 原文范围

新档案保存所选会话、分支及消息编号，原文仍来自本机已导入的对话。不会因为加入上下文而自动带入未选择的消息或其他分支。旧档案缺少完整选择记录时，只使用现有条目能可靠关联的来源；不能确认的原文不补写。

原话按完整片段选取，不把截断后的半句话当成完整原文。原文缺失、来源有歧义或片段过长时会说明；已有事实档案保持可用。手动修订与删除应继续受到保护，旧原文不能用于悄悄覆盖修订。

导出中的历史原话保留发言角色，与当前补充内容分开。自动线索保留变化过程：较后的明确纠正仅对同一事项优先，不把不同主题或不同分支互相覆盖。续聊指引要求接续具体话题，保留不确定性，并依据最后发言及“接下来想说的话”决定怎样开始。不编造共同经历、关系身份或亲密承诺。

## 保存与兼容

选择范围、续聊设置和自动线索随档案、历史版本及备份保存。设置需要 1.0.4 或更新版本，自动线索分类需要 1.0.5。1.0.6 导出的格式3备份需要1.0.6或更新版本恢复，以保留重整任务的保护规则；旧格式1/2仍可在新版读取。已明确取消的片段选择和手填内容不会因升级重新设置。原文打包继续保留已选择的原文，不因开启功能重复堆叠相同对话。

## 体验验证

工程检查覆盖原文角色与顺序、选择范围、分支隔离、修订保护、设置保存和恢复，以及窄屏上的预览与操作。是否减少陌生感，需要结合实际续聊反馈判断：前几轮是否少补背景、是否接住未完的话题、是否出现无依据的熟悉表达。语法或结构验证不等于情感体验已经得到证明。
