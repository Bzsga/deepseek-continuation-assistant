# 续聊质量评估

产品目标是减少补背景、重复纠正和讨论倒退，并保留适合当前情境的交流方式。结构合法、引用编号有效、首句自然，都不能单独证明实现了这个目标。

## 对照方法

使用合成材料或另有明确授权的样本；固定接收模型、模式、下一句话和观察轮数。对比当前导出、较短的相关材料和改进导出，观察新会话前3–5轮。记录生成差异与失败，不把没有有效回复的请求当作有效样本。不得为评测重发用户失败或计费未知的任务。

每组记录：

1. 是否回应当前问题，是否把旧问题当成尚未回答。
2. 用户需要补充多少已有背景、是否重复纠正同一要求。
3. 已定事项、未采纳建议、被排除方案及理由是否仍有区别。
4. 一次情境下的交流方式是否被错误套用于所有话题。
5. 是否编造共同经历、已采取行动或关系承诺。
6. 导入到能继续聊的耗时、实际调用次数与恢复成本。

## 代表场景

- 决定与理由：日期已因排班确定；某场地因材料限制排除；采购负责人只是建议且没有同意。接续时应保留这些状态，避免重开已定日期或把建议写成决定。
- 理解与行动：用户明确希望先理解分歧，暂不列行动清单。历史助手曾经给过建议，不能让这种观察覆盖当前要求。
- 条件化风格：技术问题希望直接给结论，个人话题希望先听完整。两种情境分别保留，不能压成永久单一人设。
- 长聊天：当前讨论关联的较早背景应有机会进入材料，近来的无关内容不能仅凭新近程度占满预算。
- 再次迁移：同一来源的重复原文跳过，真正新增部分从原文整理；手改、删除和固定继续有效。

## 自动化证据的边界

单元测试覆盖选材、来源范围、格式和保护规则；设备测试覆盖真实Room与界面操作，使用假网络。真实模型小样仅证明对应样本实际返回情况。官方App的接续质量与熟悉感需要实际接收端对话证据；不以测试计数替代该结论。
