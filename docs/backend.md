# 自托管整理后端

后端使用 FastAPI 和 SQLite。Android 负责分段、本地保存与续聊导出；每个后端任务只处理一段消息，最多发起一次上游请求。完整 HTTP 结构见 [contracts.md](contracts.md)。

原版公开入口为 [https://digimonlegend.com/continuation-api](https://digimonlegend.com/continuation-api)。下述环境值是源码默认值或配置示例，**不表示原版服务当前配置或可用额度**。

## 本地启动

需要 Python 3.10+。在 `backend` 目录创建并激活虚拟环境后：

```text
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1 --no-access-log --no-proxy-headers
```

`.env.example` 只是模板，程序不会自动读取。需要把变量传给启动进程。默认真实 API 关闭；本地模拟可设置 `MOCK_MODE=true`，模拟结果明确标记且不调用上游。测试依赖及运行方法见 [building.md](building.md)。

同一 SQLite 数据库只运行一个服务实例和 Uvicorn worker，文件锁会阻止重复实例。进程内默认两个执行协程，`WORKER_CONCURRENCY` 支持 1～5；每段独立预约、原子领取及计次，不通过增加 Uvicorn 进程扩并发。数据库路径默认是相对路径 `data/companion.sqlite3`；部署时使用持久存储，并将数据库、环境配置及备份保持私有。

## 启用真实服务

| 配置 | 用途 |
| --- | --- |
| `API_ENABLED=true`、`MOCK_MODE=false` | 启用真实调用 |
| `BASE_URL`、`MODEL`、`API_KEY` | 运营者自己的 HTTPS 兼容上游及密钥 |
| `PUBLIC_ENABLED=true` | 开放匿名计次模式 |
| `DAILY_LIMIT`、`USER_DAILY_LIMIT` | 全站与个人每日次数；源码默认 50/5，0 表示无可用容量 |
| `CONTEXT_TOKENS`、`MAX_OUTPUT_TOKENS` | 上下文和输出预算，应依据所选上游能力设置 |
| `PROVIDER_TIMEOUT_SECONDS` | 请求总时限 |
| `WORKER_CONCURRENCY` | 进程内同时执行的模型请求数，默认 2，范围 1～5；修改后重启生效 |
| `ADMIN_PASSWORD_HASH` | 手机开发者入口的管理员密码摘要 |
| `INPUT_PRICE_PER_MILLION`、`OUTPUT_PRICE_PER_MILLION` | 可选的人民币/百万 token 单价，用于金额估算 |

不要把 API Key 写入 APK 或公开仓库。运营者自行承担上游费用；匿名身份不是跨设备的自然人身份，同一人重装或换设备可能取得新身份，全站限额仍需独立设置。

对外提供服务应使用 HTTPS 反向代理，应用进程绑定私有监听地址，保留 `--no-proxy-headers`。当前管理限流只在 socket 来源为 loopback 时信任代理覆写的 `X-Real-IP`；代理必须覆盖客户端提供的此头部。普通写入保留请求体大小上限，只有反馈提交路径需要 4.5 MiB。不要在访问日志、错误日志或磁盘缓冲中记录请求正文、密钥及 bearer。

`GET /health` 用于健康检查；worker 异常停止或清理器出错时返回 503。仓库提供 Dockerfile，但现有发行验证不包含容器构建结论。

## 管理登录

管理员密码使用随机 16 字节盐及 PBKDF2-SHA256（600000 次），格式为：

```text
pbkdf2_sha256$600000$<URL-safe Base64 salt，无等号填充>$<URL-safe Base64 digest，无等号填充>
```

可在可信本机 Python 环境运行以下代码生成摘要，再通过私有进程环境设置 `ADMIN_PASSWORD_HASH`：

```python
import base64, getpass, hashlib, secrets
salt = secrets.token_bytes(16)
digest = hashlib.pbkdf2_hmac("sha256", getpass.getpass("Admin password: ").encode(), salt, 600000)
encode = lambda value: base64.urlsafe_b64encode(value).decode().rstrip("=")
print("pbkdf2_sha256$600000$" + encode(salt) + "$" + encode(digest))
```

`POST /v1/admin/login` 成功后返回 12 小时管理员 bearer 会话；服务端只保存会话摘要。五次近期登录失败会触发来源地址限流。可选 `ADMIN_TOKEN` 是独立运维凭据，不应放入普通客户端。

`GET/PATCH /v1/admin/config` 用于运行配置。上游密钥只写入，响应仅显示是否配置。SQLite 内的运行时覆盖值优先于环境默认值，重启不会把它们重置。管理界面的统计和用户列表仅提供匿名身份与用量，不提供聊天正文。

## 计次、幂等与恢复

- `POST /v1/sessions` 创建匿名凭据；`GET /v1/quota` 返回服务状态及个人/全站已用、预留和剩余次数。按北京时间零点划分日期。
- `POST /v1/jobs` 在事务中预留一次；派发前重新检查配置和额度，再把预留转为已用。已派发的失败、取消或不确定请求仍计次。
- 同一用户、相同幂等编号及内容返回原任务，不重复预留；相同编号改内容返回 409。排队取消释放预留，启动后的请求不自动重发。
- `GET /v1/jobs/{id}` 和取消接口仅对所属身份开放。到期任务及同编号重放返回 410。
- 上限降低或模型配置变化可能使旧排队任务失效并释放预留；已开始任务保留原配置快照。提高次数后，客户端须重新读取配额，已用次数不会被清零。
- 重启把原运行中任务标为 `uncertain`，保留必要账务；已完成片段由客户端保留。跨日未开始的预留继续占用容量。

请求还受正文字符数、消息条数、请求体字节数和实际模型上下文限制；详情见协议，不应只通过增大输出预算解决所有错误。

## 模型输出与用量

每次请求将来源编号映射为短别名 `m1/m2…`，返回后严格还原。可无歧义还原的字段别名、包装层和分类差异会归一化；未知来源、无法归一化的必需字段错误或无效 JSON 会失败。支持完整代码围栏及已知边缘格式字符，不会从自然语言中提取片段当作成功结果，也不自动调用模型修复。具体兼容边界见下文“模型输出的结构兼容”。

新整理任务保存提示协议 v8，旧 v2–v7 任务保留原提示与预留边界。常规诊断仅记录类型、大小、位置、网络阶段及版本等受限元数据。DeepSeek 兼容参数是否被第三方网关采用，取决于实际服务实现。

`usage_known` 和 `cost_known` 独立。用量必须是完整、不冲突的输入/输出配对。未知用量的 0 是占位值，不代表免费；token 统计只累计可信部分。公开计次且单价未配置时，完整结果经结构与来源校验后可以在未知用量下交付；历史金额模式则继续保留不确定费用预留。

## 保留与扩展接口

终态任务正文和整理结果 24 小时后过期，清理器删除内容，保留幂等与账务元数据；上游服务商的保留政策另计。失败/不确定请求可另存必要请求与有界原始响应，默认24小时，仅通过受限工具读取，详见 [私有失败留存](failure-replay.md) 和 [隐私说明](privacy.md)。成功请求不新增该副本。

[意见箱](feedback.md) 和 [诊断](diagnostics.md) 使用独立数据表与限额，不消耗模型次数。反馈 worker 接口仅提供已批准内容的领取与结果回写；Web 服务本身不会执行提交者命令，也不附带任何已启用的自动开发任务。自行接入 worker 时需要独立授权与私有密钥管理。

历史邀请码及金额账务仍保留，公开模式关闭时可使用 `python -m app.admin` 的 `invite`、`cap`、`uncertain`、`reconcile`、`purge` 子命令；先查看各命令 `--help`。金额核对只依据实际账单结算，不重新发送模型请求。

## 模型输出的结构兼容

后端在严格的来源映射前做有限结构归一化：识别明确的条目数组、单层结果包装、条目字段别名和按现有类别分组的结果。正文和来源必须完整保留；缺失的展示类别可归入续聊事项，缺失或未知的事实类型保守标为未确认，不推断为用户事实。缺失、空或未知来源、冲突字段、歧义结果和不完整条目仍会暂停，不能通过补空数组或虚构引用伪装成功。

新整理任务使用版本 8 提示，末尾明确正文、前段参考和来源要求，并在同次整理中识别交流线索与回应方式；条目数量和正文仍受软预算约束。旧版本 2–7 任务继续使用其创建时的请求字节和预留，不更换已有任务的服务配置或费用状态。模型输出仍可能失败，这些规则不等同于对语义正确性的保证。

对字段名漏掉开头双引号、但保留闭引号和冒号的格式错误，仅在严格JSON解析器确认的对象属性位置，为已知协议字段补一个引号；最多修复40处，每次完整重解析。不会搜索替换正文字符串或补造来源。其他语法错误、冲突重复字段、结构和来源校验继续生效；解析阶段的固定诊断为 `json_missing_key_quote`，整个结果通过后才返回兼容提示。

成功兼容后的 HTTP 返回仍是标准 entries，现有 Android 可直接读取。启用失败留存以前被丢弃的响应不能追溯重解析；有未过期快照的新失败可离线排查。常规诊断只保存固定结构类别、白名单字段类型和数量。

## 长文本并行整理

Android 1.0.3 起配套服务默认同时处理2段，分别保存完成结果，再按原片段顺序聚合。任一段失败后停止派发新段，已发出的其他段继续收尾；恢复时优先查询已有任务编号，未知提交保留原内容和幂等键。取消会处理全部未完成远端编号。自配 API 仍串行。

调度能力上限为5，实际吞吐受上游排队、缓存和账号并发策略影响；更多并发不保证更快。增加等待时限只延长同一次调用，不自动重发，也不增加该段的请求次数。自托管应根据实际的上游延迟配置等待时限，保留每段的输出与次数上限。

## 长文参考与可选政治议题检查

额度响应通过 `organization_protocol_version=10` 告知客户端可使用原话优先、用户对“你”回顾的整理；版本 8 起支持长文参考。整理请求的 `context_messages` 是可选的前段引用，最多 800 字符，与正文合并计算上下文预算；保留结果至少需要一个正文来源，纯参考条目不重复归档。参考仍属于同一次请求，不额外调用模型；不支持该能力的旧服务由新版客户端使用原有整理路径。

额度响应中的 `political_filter_supported=true` 表示支持独立的政治议题检查。客户端明确开始后，以 `operation="political_filter"` 提交到原 `POST /v1/jobs`，每批最多 12 个片段、6000 字符，没有 `context_messages`。后端使用独立协议 1，BYOK 对应 `political-filter-v1`，与普通整理的 v8 提示分开；返回值只标记片段和原因，模型不提供替换文字。

检查使用同一鉴权、预算、计次、幂等、取消、过期与诊断机制，每个已派发批次正常消耗一次请求。原请求身份包括操作类型，不能把整理请求和政治检查混用同一幂等编号。没有命中表示本次未标记片段，不代表内容一定符合其他平台规则。普通个人资料、名称或中性历史语境不应仅因关键词被标记；存在误判或漏检的可能。

## 可选自动备用线路

只有管理员明确配置备用线路后，公开且未配置金额单价的整理才启用自动切换；历史金额模式、模拟模式及自配API保持单路。通过环境变量 `FALLBACK_PROVIDERS_FILE` 指向服务器私有JSON文件，文件须为服务用户所有的普通文件，权限0600，且不能放进源码或APK。文件包含 `providers`（最多两条备用，每条含id/base_url/model/api_key，可选timeout_seconds/context_tokens/max_output_tokens）、`order`（包含primary与各备用id）、`slow_seconds`（默认30）、`cooldown_seconds`（默认300）。部署前应在相同合成资料上比较有效结果的耗时再设置顺序。

前置线路达到切换时限后停止等待，再派发下一条；末路最多90秒，每段最多三条独立线路，同一线路不重复派发。异常或超时线路临时降序，冷却结束后回到配置顺序。只交付通过现有结构和来源校验的结果。取消本地等待不能保证上游不计费。每次派发前都原子检查任务取消、配置和全局/用户额度，并保存不可重用的尝试身份；重启不重发未确认尝试。

配额返回 `automatic_fallback_enabled` 和 `max_attempts_per_chunk`，供新版客户端显示N～3N的请求范围；原模型与上下文预算保持稳定，避免旧任务因动态路由而改变身份。每次实际派发分别计次，管理统计按尝试记录用量；未知用量保持未知，不按原线路单价计算备用模型费用。BYOK不采用服务器备用凭据。
