# 应用更新与 Fork 发布

原版更新清单为 [latest.json](https://digimonlegend.com/continuation-updates/latest.json)，APK 使用同站点的独立版本目录。开源仓库的下载入口为 [GitHub Releases](https://github.com/Bzsga/deepseek-continuation-assistant/releases)。

这些是原版分发渠道。Fork 不应向原版托管服务发布，也不能使用自己的签名覆盖原版应用。

## 手机端行为

带更新模块的客户端在启动或返回前台时静默检查，自动检查最多每五分钟一次；“设置 → 关于”也可手动检查。提示可以稍后处理，只有点击下载才开始传输。

APK由Android系统下载管理器传输，可切到后台，网络暂停时等待系统恢复。任务编号和更新信息持久保存在不参与备份的私有目录；重新打开应用查询同一任务，支持取消和失败后手动重试。系统先保存至应用专属外部文件目录，完成后有界复制至私有缓存，再检查大小、SHA-256、包名、版本、最低 Android 要求和与当前应用一致的签名，安装前再次校验。

更新清单仍拒绝跳转；APK起始地址限定为配置的HTTPS版本目录，传输与重定向由系统下载管理器处理。更新下载没有聊天或服务凭据，只有最终完整验证通过的私有APK可进入安装流程。系统通知只显示进行中的下载，不直接打开未验证APK。

后台下载修复在安装1.0.10后生效。首次从旧版升级本次，请保持旧版在前台下载，或在浏览器下载同签名APK覆盖安装。

系统安装由用户确认，必要时需先允许安装未知应用。正在整理、检查温和版、保存或处理外部导入时暂缓安装。更新不携带聊天或整理服务凭据，不消耗模型次数，不触发模型重试。

早期 preview.6 及以前版本没有更新模块，需要一次手动同签名升级；之后可以使用应用内检查。

## 1.0.12 原话回顾与界面精简

新整理尽量保留原话，以“我、你、我们”回顾讨论，保留犹豫、条件、纠正和未定事项。首页突出导入；结果页、条目操作和设置收拢低频入口。旧档案、手改与未完成请求身份保留，升级不自动重新整理。备份继续写格式6、读1–6；含新版v1.6整理任务时请用1.0.12或更新版本恢复。

## 1.0.11 快速接续与增量补聊

准备页可选“先快速接续”，已有档案可“补入最近聊天”，接话不顺可在当前聊天使用“没接上？调整一下”。快速接续和修正材料均在本机生成；智能整理保留讨论进展，并仅对核实后的新增消息发起请求。配套服务自动备用时显示请求次数范围，实际派发逐次计数。

本版写入格式 6 备份，可读取格式 1–6；恢复新备份需要 1.0.11 或更新版本。升级不会自动请求模型，原签名与本地资料继续保留。

## 1.0.10 后台下载与自然接话

本版合并系统后台下载及续聊开场调整：首轮参考已有对话语气自然接上一两句，有明确待回答问题或手填的下一句话时优先回应；“我回来了”是可选表达，不是固定台词。主流程不增加填写步骤。

更新相关31项JVM与既有32项指令检查通过；Android11隔离测试验证同一任务在应用进程退出后继续下载、恢复及有界私有复制，保留包身份校验。正式构建、lint、原证书验签和1.0.9覆盖升级通过；这些结果不代表所有实体手机后台策略或真实续聊语气均已验证。

## 1.0.9 升级与备份兼容

1.0.9 在本机改进续聊内容选择：代表问答覆盖不同已有线索，明确修正按来源集中保留，接续提示依据真正附带的最后发言。最近问答过长时可以携带明确标记的原文句段节选；手动选择及关键原话仍整段处理。

长摘要默认为互动与最近话题预留空间，整条选择自动记忆，并显示本次未附带数量。手填、修改、固定资料及明确要求优先保留，软长度目标可以超出；需要时可选“带上全部记忆”。原文模式保持完整，原档案和备份不受携带选择影响。短文直接复制并打开，长文保存后打开；调整等次要操作收进更多，进度恢复仍保持可见。复制和保存使用当前预览对应的完整导出文本。

本次没有增加模型请求，也不修改后端 v8 / BYOK v1.4 整理协议。1.0.8 引入的长文跨段参考和可选“生成温和版”继续沿用；温和版检查仍需主动开始，单独显示预计次数并正常计次或计费，不能保证其他平台接受文本。

回应方式在原有整理请求内提取，只有至少两条不同的助手原话支持、来源版本与范围明确的观察才作为自动回应方式；它不表示用户认可或关系承诺。默认附带最多 4 条去重后的代表，其余条目仍保存在档案。仅因代表数量限制而未附带时，也能选择“带上全部记忆”恢复；仍遵守“参考旧助手的回应方式”等已保存开关。

主流程不增加设置步骤。“调整（可选）”中的“参考旧助手的回应方式”可单独关闭；关闭后，有效自动回应方式不再导出，也不回落到事实段。条目仍保留，手动修改和明确选中的原话继续按原有规则处理。升级和重新整理保留已有整体关闭状态及明确保存的回应方式关闭状态，不因升级自动请求模型。

1.0.9 继续导出格式 5 备份，需要 1.0.8 或更新版本恢复；新版读取格式 1–5。温和版检查记录只在当前设备保存，不包含在档案备份中。恢复新版备份前，请先升级应用。

## 已有档案重新整理

1.0.6 新增已有档案的“重新整理”。升级本身不会重新请求模型；在确认原文范围、服务及预计请求次数或费用后，点击一次“确认并重新整理”才开始。免费服务按实际发出的请求计次，BYOK 按服务方实际使用计费。

重新整理另存新版，原档案继续保留。新版继承手动修改、删除、固定条目和个人设置；来源范围无法可靠恢复时，需要明确重新选择。冲突默认保留已有内容，具体行为见[重新整理已有档案](conversation-continuity.md#重新整理已有档案)。

1.0.6 曾使用格式 3 备份来保护重新整理任务的状态；当前版本继续读取这些备份。

## 清单协议

清单是严格 UTF-8 JSON，最多 32 KiB。

| 字段 | 要求 |
| --- | --- |
| `schemaVersion` | 1 |
| `packageName` | 与实际 APK 包名一致 |
| `versionCode`、`versionName` | 来自 APK 的真实版本 |
| `apkUrl` | 配置允许的同 origin、版本化 HTTPS APK 地址 |
| `apkSize` | 实际字节数，最多 64 MiB |
| `sha256` | 小写 64 位 SHA-256 |
| `minSdk` | APK 最低 API，当前 Android 源码为 26 |
| `releasedAt` | UTC ISO 8601 时间 |
| `changelog` | 最多 8 条、每条最多 200 字符的非空说明 |

清单使用 `Cache-Control: no-store`；版本化 APK 应不可覆盖，使用正确 APK Content-Type 和长期 immutable 缓存。先放置完整 APK，再原子替换清单，避免清单指向尚未上传完成的文件。

## 版本与签名

当前 Android 源码为 1.0.14 / versionCode 23。自 1.0.1 起使用递增数字 `major.minor.patch`，每次发布递增 versionCode，至少推进 patch。设置页显示实际 BuildConfig 版本。桥接测试属性 `updateTestVersionCode` / `updateTestVersionName` 只用于本地升级验证，不作为正式发布版本。

`tools/verify_release.py` 调用 Android SDK 的 `apksigner` 与 `aapt2`，生成和 APK 哈希绑定的验证元数据。现有工具固定了原版包名与公开证书摘要；Fork 必须替换为自己的身份与证书，不能仅改清单跳过验签。私钥和密码不属于源码。

## 发布工具

`tools/publish_release.py` 检查 APK/元数据哈希、ZIP 结构、版本及签名连续性，支持先进行本地预览：

```text
python tools/publish_release.py publish --apk <APK路径> --verified-metadata <验证JSON路径> --changelog-file <说明JSON路径> --dry-run
```

说明文件是 UTF-8 JSON 字符串数组。`--dry-run` 不上传，远端冲突仍需实际发布时检查。发布器的远程能力依赖运营者提供的可信 `--ssh-helper`；该 helper、服务器凭据和原版托管权限不随仓库提供。

Fork 使用前必须先检查并配置发布工具中的域名、静态目录、站点配置、包名和证书约束，再配置 Android 的更新清单与下载来源限制。构建签名见 [building.md](building.md)。不要直接把为原版编写的托管准备流程运行到其他现有网站。

发布流程按上传暂存、核对哈希、取得发布锁、落盘不可变版本目录、原子更新清单的顺序进行。相同版本和相同内容可以幂等重试；同版不同内容、降版或签名变化会拒绝。更新发布与整理后端配置、数据库和账务分离。

合成发布器回归位于 `tools/tests/test_publish_release.py`；既有发行验证范围见 [README](../README.md#验证状态与局限)。这份文档不包含原版部署记录或私有运维路径。
